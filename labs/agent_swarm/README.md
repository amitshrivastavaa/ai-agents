# agent_swarm — a multi-agent deliberation engine

> A panel of specialist agents argues your question over three rounds, then a
> moderator synthesizes a decision record: verdict, confidence, consensus, and
> the dissent you shouldn't ignore.

Inspired by the viral **TradingAgents** "LLM trading firm" — a desk of analyst
agents that debate and vote — generalized into a reusable engine for *any*
high-stakes call: trades, hires, architecture choices, product bets, deals.

Runs **fully offline** with the Python standard library (no API key, nothing to
install). Set `ANTHROPIC_API_KEY` to route the same personas through a real
model instead.

## Quick start

```sh
# A scripted tour across five panels
python -m labs.agent_swarm.demo

# One question, full transcript
python -m labs.agent_swarm.cli --panel trading "Go long NVDA into earnings?"

# Machine-readable decision record
python -m labs.agent_swarm.cli --panel vc --json "Lead the seed in an AI devtools startup?"

# List the panels
python -m labs.agent_swarm.cli --list
```

## How a deliberation works

1. **Opening statements** — every persona states a stance (an opinion meter
   from *against* to *for*), a thesis, and supporting points.
2. **Cross-examination** — each persona challenges its furthest opponent and
   reinforces its closest ally (⚔️ rebut / 🤝 co-sign).
3. **Revision under pressure** — confidence and stance drift with the net
   agreement each persona received: a small model of persuasion.
4. **Vote & synthesis** — the moderator computes a confidence-weighted score,
   maps it to the panel's verdict scale, and reports consensus and live dissent.

## The panels

| Panel | Verdict scale | The room |
| --- | --- | --- |
| `trading` | STRONG BUY → STRONG SELL | fundamentals, momentum, sentiment, risk, macro, a contrarian short-seller |
| `hiring` | STRONG HIRE → NO HIRE | hiring manager, bar raiser, peer, team lead, recruiter |
| `architecture` | ADOPT / TRIAL / ASSESS / HOLD | early adopter, pragmatist, security, SRE, data architect |
| `product` | SHIP → KILL | PM, design, growth/data, eng lead, voice of support |
| `vc` | INVEST-LEAD → PASS | GP, LP-minded skeptic, market, technical DD, operator |

## Why it's interesting offline

Each persona's stance is a transparent function of three things: its **bias**
(resting lean), its **sensitivity** to the question's **signal** (a lightweight
sentiment read of your wording), and small deterministic jitter. So:

- The same question always yields the same debate — reproducible and testable.
- Bullish wording ("record growth, durable moat") pushes the room toward *for*;
  bearish wording ("lawsuit, overvalued, crowded") pushes it toward *against*.
- A **contrarian** has *negative* sensitivity, so it leans against the obvious
  read — and shows up as the lone dissenter when the room piles onto one side.

Every vote is explainable, which is exactly what you want from a decision
support tool you don't fully trust yet.

## Going online

When `ANTHROPIC_API_KEY` is set and `anthropic` is installed, each persona's
opening is generated by the model (same `Argument` shape: stance, confidence,
thesis, points), with a silent fallback to the offline path on any error. The
orchestration, persuasion model, and synthesis are identical — only the source
of each opening changes.

## Extending it

Add a panel in `personas.py`: a tuple of `Persona`s (each with a `lens`,
`bias`, `sensitivity`, and `priorities`) plus a `verdicts` scale. The engine
and CLI pick it up automatically.
